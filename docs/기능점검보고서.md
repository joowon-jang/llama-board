# llama-board 기능 점검 보고서

| 항목 | 내용 |
| --- | --- |
| 점검일 | 2026-08-30 |
| 대상 | `llama-board` 0.1.4 |
| 점검 범위 | React/TypeScript UI, Tauri command wiring, Rust native layer, 저장·보안·오류 경계 |
| 점검 방식 | 소스 추적, 명령 연결 대조, Rust 테스트/formatter/linter, 프런트엔드 typecheck/build/lint/Vitest, Vite 브라우저 smoke, runtime/API smoke |

## 1. 결론

기능 명세서는 [`기능명세서.md`](기능명세서.md)로 작성했다. 소스 기준으로 주요 기능은 구현되어 있으며, 점검 중 발견한 실제 결함 6개 범주를 수정하고 로케일 불일치 테스트 1건을 정리했으며, 현재 선택 runtime 설정도 실행 가능한 조합으로 정규화했다.

1. 상단 `적용 및 재시작` 버튼이 모델 Library로만 이동하고 Tuning의 `applyRestart`를 호출하지 않던 문제를 수정했다. 이제 Models > Tuning으로 이동하고 `applyRequest`를 전달해 실제 적용·재시작을 시작한다.
2. MCP 승인 정책 요약 카드가 사용자의 선택과 관계없이 `Always ask`로 표시되던 문제를 수정했다. 이제 `always-ask`, `once`, `session`, `server-tool`, `deny` 중 현재 정책을 표시한다.
3. 실행/모델 프로필의 표시 문구를 i18n catalog로 통일하고, 프로필 복제 직후 선택 상태가 저장되지 않던 문제와 빈 stop 문자열이 이전 값을 유지하던 문제를 수정했다.
4. Tuning 적용 실패 시 일부 server 설정만 복원하던 문제를 수정해 전체 server 설정 snapshot을 rollback하도록 했다.
5. 저장 설정이 `rocm/b10655`와 DFlash2 draft 모델 조합으로 불일치하던 상태를 `rocm/pr27342`로 정규화했다. `pr27342` runtime probe와 실제 서버 기동이 정상이며, `b10655`는 번들 vendor library/kernel data가 없어 preflight 실패하는 상태로 확인했다.
6. Windows headless CLI가 WMI 권한 거부 환경에서 실행 중 서버를 `crashed`로 오판하던 문제를 수정했다. Win32 `QueryFullProcessImageNameW` 기반 PID 실행 파일 검증과 회귀 테스트를 추가했고, 이후 `server status`가 `running/health:true`를 반환했다.

Rust native 계층은 전체 테스트·formatter/linter·CLI build를 통과했다. 번들 Node.js v24.19.0을 절대경로로 사용해 프런트엔드 typecheck/build/lint/Vitest도 통과했고, Vite 브라우저 preview에서 주요 화면 전환·언어 선택·콘솔 오류 여부를 확인했다. 재빌드한 CLI로 실제 headless server를 기동해 `/health`, `/v1/models`, `/v1/chat/completions`를 확인한 뒤 정상 종료했다. 다만 이 환경의 `cmd` PATH에는 `node`/`npm`이 아직 반영되지 않았고, 패키지된 Tauri 창에서만 가능한 native picker·실제 invoke·beforeunload UX는 별도 수동 범위로 남긴다.

### 3.2 Gated 테스트와 실제 smoke 구분

- `src-tauri/tests/runtime_install.rs`: `LLAMA_BOARD_RUNTIME_INSTALL=1`이 없어서 실제 GitHub runtime 다운로드·설치·preflight를 skip했다.
- `src-tauri/tests/smoke.rs`: `LLAMA_BOARD_SMOKE=1` 및 `LLAMA_BOARD_SMOKE_MODEL`이 없어서 실제 llama-server 기동·스트리밍 채팅을 skip했다.
- 따라서 위 두 테스트의 test harness 결과는 exit code 0이지만, gated body 실행의 증거로 해석하지 않는다.
- 대신 재빌드한 CLI와 저장된 `rocm/pr27342` 설정으로 실제 headless server를 실행했다. `/health`는 `status: ok`, `/v1/models`는 선택 GGUF를 반환했고, `/v1/chat/completions`는 정상 JSON completion과 usage를 반환했다. 이후 `server stop`으로 프로세스를 종료했다.
- 재검증 중 WMI 권한 거부로 `server status`가 live server를 `crashed`로 오판하는 결함을 발견·수정했다. 수정 후 `server status`는 `managed:true`, `state:running`, `health:true`를 반환했고 `server stop` 뒤에는 `managed:false`, `state:stopped`를 반환했다.
- `runtime probe rocm/pr27342`와 `runtime probe vulkan/b10638`은 `available`, diagnostics empty, benchmark available로 통과했다. `rocm/b10655`는 번들 vendor library/kernel data 누락으로 `failed preflight`가 재현됐다.
- Vitest 최초 재시도에서는 `initialLocale: "en"`으로 렌더한 테스트가 한국어 제목을 고정 검색하는 assertion 불일치 1건을 발견했다. 테스트 기대값을 영어 로케일에 맞게 수정한 뒤 12개 파일·61개 테스트가 모두 통과했다.
- Vite browser preview에서는 네이티브 런타임이 없는 환경에서 안내 배너가 표시되었고, Chat/Models/Developer/Settings 주요 탭, Models의 Library/Tuning, Settings 언어 선택 및 저장 상태를 확인했다. 브라우저 콘솔 error/warn은 0건이었다.

### 3.3 실행 차단

이 환경의 `cmd` PATH에는 아직 `node`/`npm`이 없어 npm script 진입점은 직접 실행하지 못했다.

```text
npm test
npm run typecheck
npm run build
npm run lint
node_modules\\.bin\\tsc.cmd --noEmit -p tsconfig.json
node_modules\\.bin\\vitest.cmd run
node_modules\\.bin\\eslint.cmd src
```

대신 프로젝트에 설치된 의존성을 사용해 다음 번들 실행기를 직접 호출했다: `C:\Users\joojoo\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe` (`v24.19.0`). 이를 통한 typecheck/build/lint/Vitest와 브라우저 smoke는 모두 통과했으므로 프런트엔드 실패가 아니라 PATH 반영 지연/세션 환경 차이로 분류한다.

## 4. 정적 연결 점검

- `src/api.ts`의 Tauri invoke wrapper와 `src-tauri/src/lib.rs`의 `generate_handler!` 명령 목록을 대조했다.
- Models, Discover, Runtimes, Bench, Projects, Developer, MCP, Settings의 화면 진입점과 native API 호출을 대조했다.
- `TuningPanel`이 파일에만 존재하고 앱에서 mount되지 않던 상태를 확인한 뒤 App 라우팅에 연결했다.
- 실행/모델 프로필의 i18n, 복제 선택 저장, stop 문자열 clearing 및 Tuning 전체 설정 rollback을 소스와 직접 대조했다.
- headless 상태의 PID 실행 파일 검증을 WMI가 아닌 Win32 native API로 확인하고 현재 실행 파일 회귀 테스트를 통과시켰다.
- `AppConfig` normalize/validate, config save queue, path containment, file identity, bounded reader, secret redaction, runtime provenance를 소스 및 Rust 테스트와 대조했다.
- SSE/OpenAI/native/Anthropic adapter, chat/document index/project/profile 유틸과 해당 테스트 파일의 존재를 확인했다.

## 5. 잔여 리스크와 권고

### P1 — Node/npm PATH 반영 필요(검증은 완료)

현재 Codex 프로세스에서는 `node`와 `npm`이 PATH에서 인식되지 않지만, 번들 Node 직접 실행으로 아래 동등 검증은 완료했다. 새 터미널 또는 CI에서는 npm script 진입점도 한 번 확인한다.

```powershell
npm run typecheck
npm run build
npm run lint
npm run test
npm run test:ui
```

그 다음 패키지된 Tauri 앱에서 Models > Tuning, 상단 Apply & restart, MCP 각 승인 정책, Runtimes 취소/선택, Chat 첨부·도구 승인, 실제 file picker와 beforeunload stop을 수동 확인한다. 브라우저 preview에서 native runtime unavailable 안내와 주요 화면 전환은 이미 확인했다.

### P2 — 외부 runtime 설치 경로

이번 점검은 이미 설치된 runtime으로 probe와 실제 API smoke를 완료했지만, GitHub release에서 runtime을 새로 다운로드·설치하는 gated 경로는 실행하지 않았다. 배포 후보를 확정할 때만 `LLAMA_BOARD_RUNTIME_INSTALL=1`로 별도 검증한다.

### P2 — 수동 UX 회귀

브라우저 preview에서는 주요 탭·ARIA 구조·언어 선택·native unavailable banner를 확인했고 콘솔 error/warn도 없었다. 좁은 창 반응형 레이아웃, focus 복귀, `beforeunload` stop, 실제 file picker와 dialog 동작은 패키지된 Tauri 앱에서의 수동 회귀 대상으로 남긴다.
