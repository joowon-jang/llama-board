## 1. 제품 목적과 범위

llama-board는 로컬 GGUF 모델과 llama.cpp 런타임을 설치·선택·실행하고, 로컬 인증 API를 사용하는 채팅 및 개발자 도구를 제공하는 Windows 데스크톱 애플리케이션이다. llama.cpp 자체를 재구현하지 않고 공식 서버·벤치마크 바이너리를 관리한다.

제품의 기본 네트워크 경계는 다음과 같다.

- 관리 서버는 `127.0.0.1`에만 바인딩한다.
- 데스크톱 앱이 시작할 때 프로세스 단위 Bearer 토큰을 생성하고 현재 WebView에만 전달한다.
- 토큰은 설정 파일·로그·내보내기 결과에 저장하지 않는다.
- 외부 통신은 Hugging Face 모델 조회/다운로드 및 GitHub 런타임·PR 조회/다운로드에 한정한다.
- 브라우저 미리보기에서는 Tauri native 명령, 로컬 파일, 로컬 모델 서버를 사용할 수 없으며 안내 상태를 표시한다.

## 2. 사용자와 핵심 사용 흐름

### 2.1 사용자 유형

| 사용자 | 주요 목적 |
| --- | --- |
| 로컬 사용자 | 모델 선택, 서버 시작, 채팅, 문서·이미지 첨부, 프로젝트 관리 |
| 개발자 | OpenAI/Anthropic 호환 API 확인, curl·Python·JavaScript 예제 복사, MCP·게이트웨이 점검 |
| 런타임 관리자 | GPU별 런타임 설치·선택, PR 빌드, portable ZIP 이동, capability preflight |
| 헤드리스 사용자 | `llama-board-cli.exe`로 설정·모델·런타임·서버 상태 관리 |

### 2.2 서버 상태 전이

```text
앱 시작 → 설정 로드 → stopped
                         ↓ start
                       starting → running → stopping → stopped
                           ↓          ↓            ↓
                       failed      crashed      failed
```

- `starting`, `stopping` 중에는 중복 lifecycle 작업을 차단한다.
- `running` 중에는 모델·런타임 교체, 프로젝트 적용, projector 변경 등 리소스 변경을 차단한다.
- 서버 시작은 선택된 GGUF 모델, 유효한 projector·LoRA, 선택된 런타임 capability를 검증한 후 진행한다.
- `/health`와 `/v1/models`를 polling하며 PID, 활성 요청 수, 메모리 추정치, idle 상태를 표시한다.
- 시작 실패·비정상 종료는 오류 상태와 진단 진입점을 제공하며 재시도할 수 있다.

### 3.2 공통 셸

- 상단 상태 표시줄: 서버 상태, 활성 요청 수, PID, Start/Stop.
- load bar: 활성 모델, backend/build, context, GPU layers, Flash Attention, 메모리.
- `Apply & restart`: Tuning 화면으로 이동하고 현재 변경사항을 실제 재시작 흐름에 전달한다.
- 오류·경고는 화면을 유지한 채 feedback banner로 표시한다.
- 탭은 최초 선택 시 lazy mount하며, 키보드 탐색·skip link·tabpanel ARIA 관계를 제공한다.
- 테마(light/dark/system), 화면 밀도, reduced motion, 한국어·영어·일본어·중국어를 지원한다.

## 5. 설정 및 데이터 계약

### 5.1 `AppConfig` 필드 그룹

| 그룹 | 필드 |
| --- | --- |
| 활성 리소스 | `models_dir`, `active_model`, `active_backend`, `active_build`, `mmproj`, `lora_adapters` |
| 서버·메모리 | `port`, `ngl`, `ctx_size`, `n_cpu_moe`, `threads`, `parallel`, `flash_attn`, `request_timeout_seconds`, `sleep_idle_seconds` |
| Sampling | `temperature`, `top_p`, `top_k`, `chat_options` |
| Speculative/MTP | `spec_type`, `spec_draft_n_max`, `spec_draft_n_min`, `spec_draft_p_min`, `spec_draft_p_split`, `spec_draft_ngl`, `spec_draft_device`, `spec_draft_model` |
| Reasoning | `reasoning`, `reasoning_format`, `reasoning_effort`, `reasoning_budget`, `reasoning_budget_message`, `reasoning_preserve` |
| 고급 실행 | `server_args`, `iters` |

공통 규칙:

- dedicated field가 관리하는 server flag는 `server_args`에 중복 지정해도 dedicated 값이 우선한다.
- host, port, model, API key 등 앱 소유 필드는 escape hatch로 덮어쓸 수 없다.
- 설정 저장은 queue로 직렬화하고 normalize/validate 후 atomic write한다.
- 서버 실행 중 projector·모델·런타임 등 프로세스 리소스 변경은 차단한다.

### 5.2 Chat 요청 계약

| 대상 | 요청 |
| --- | --- |
| llama.cpp OpenAI 호환 | `/v1/chat/completions`, Bearer, `stream: true`, sampling/chat options/도구/`reasoning_effort` 병합 |
| native llama.cpp | `/api/v1/chat`, native adapter로 reasoning/text/usage를 OpenAI 형태로 변환 |
| Anthropic | `/v1/messages`, `x-api-key`, Anthropic version header, text/reasoning/vision/tool 변환 |
| Embedding | `/embeddings`, finite vector와 입력 개수 검증 |

SSE parser는 `[DONE]` 프레임을 확인해야 정상 완료로 판정한다. 스트림 중단·네트워크 오류는 현재 메시지를 interrupted/failed 상태로 보존한다.

## 7. 런타임·보안 요구사항

- Release runtime archive는 HTTPS GitHub host, 허용된 파일명, SHA-256 digest, 필요한 실행 파일, OS/architecture를 검증해야 한다.
- PR source build는 CPU/Vulkan/CUDA/ROCm만 허용하고 SYCL/OpenVINO는 vendor compiler·환경 스크립트 의존성 때문에 사전 거부한다.
- PR 확인 화면은 PR 번호가 아닌 확인된 head commit을 신뢰 기준으로 삼는다. 재조회한 commit이 다르면 다운로드·빌드를 진행하지 않는다.
- PR build는 `llama-server`와 `llama-bench`만 Release로 생성하며 tests/examples와 embedded web UI를 끈다.
- Hugging Face 다운로드는 repository/file traversal, 허용되지 않은 redirect, collision, checksum 불일치를 거부한다.
- MCP는 shell 문자열을 실행하지 않고 직접 argv child process를 생성한다. 도구 승인 키는 server/tool identity에 결합한다.
- native 이미지·문서 read는 picker가 반환한 canonical identity와 요청 path를 비교한다.
- 서버와 gateway는 app exit 및 idle 정책에서 child process를 reap하고 API key 파일을 정리한다.

## 8. 수용 기준

릴리스 후보는 다음을 모두 만족해야 한다.

1. `npm run typecheck`, `npm run build`, `npm run lint`, `npm run test`, `npm run test:ui`가 통과한다.
2. `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`가 통과한다.
3. 실제 설치 런타임으로 `/health`, `/v1/models`, 스트리밍 chat, stop/reap smoke를 수행한다.
4. 모델 삭제·문서/이미지 read·MCP tool call·runtime import/export·PR confirmation의 경계 거부 테스트가 통과한다.
5. 한국어·영어·일본어·중국어 전환, 좁은 데스크톱 창, keyboard focus, reduced motion을 확인한다.
